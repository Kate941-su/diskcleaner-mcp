# ディスククリーンアップ手順

diskclean MCP サーバーのツール（`get_os_env_paths` / `analyze_disk_usage` / `scan_cleanup_targets` / `move_to_trash`）を使う。

## 手順

1. **対象を決める**: ユーザーが場所を指定していなければ `get_os_env_paths` で標準のキャッシュやログの場所を確認し、候補を提示する。
2. **内訳を見る**: `analyze_disk_usage(target_path)` で、どのサブディレクトリやカテゴリが大きいかを把握する。もう少し下の階層まで見たいときは `max_depth`（最大3）を指定する。深く掘るより、大きかったサブディレクトリを `target_path` にして呼び直すほうが、結果が見やすい。
3. **候補を作る（Dry-Run）**: `scan_cleanup_targets` を実行する。カテゴリ（`dev_cache` / `large_videos` / `old_logs` / `all`）や閾値はユーザーの意図に合わせる。
4. **ユーザーに確認する**: 結果を表（パス・種別・サイズ・最終更新）にして見せ、合計の削減量を伝える。**どれを移動するか、ユーザーの明示的な同意を得る**。
5. **退避する**: 同意された項目だけを、手順3の `scan_id` と一緒に `move_to_trash` に渡す。
6. **報告する**: moved / skipped / failed を報告し、ゴミ箱から復元できることを伝える。

## 禁止事項

- 同意なしに `move_to_trash` を呼ばない。「全部消して」と言われた場合も、件数と合計サイズを示して一度確認する。
- スキャン結果にないパスを `move_to_trash` に渡さない（サーバーが skip する）。
- 保護パスのエラーを、パスを言い換えるなどして迂回しない。
- `rm` などのシェルコマンドで代わりに削除しない。

## 注意

- `large_videos` はユーザーの個人データの可能性が高い。1件ずつ確認することを推奨する。
- `truncated: true` のときは、表示しているのが一部だけであることを伝え、閾値を上げるか範囲を絞って再スキャンする。
